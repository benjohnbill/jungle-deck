# jungle-deck 사용 설명서

단계마다 스킬이 무엇을 하고, 내가 무엇을 정하는지 정리한 표예요. 설치와 첫 실행은 저장소의 `README.md`를 보세요. 이 표는 요약이에요. 내용이 어긋나면 `SPEC.md`가 우선해요.

## 단계별 흐름

각 단계는 내가 확인해야 끝나요. 스킬은 내 생각과 초안에서 출발하고, 초안 안에서 또는 내가 비워 둔 칸에만 후보를 제안해요. 기록되는 것은 내가 고르거나 고쳐 쓴 내용이에요.

### grill — 내용 정하기

| 스킬이 하는 일과 묻는 말 | 내가 정할 것 |
|---|---|
| "이번 주에 발표하고 싶은 아이템이나, 대략 생각해 둔 흐름이 있어요?" (아직 아무것도 읽지 않아요) | 아이템과 흐름, 또는 "없어요" |
| "없어요"라고 하면 이번 주에 관한 질문 세 개를 해요(가장 시간을 쓴 일, 가장 어려웠던 부분, 배우고 싶었던 것). 그다음 답에서 뽑은 후보와 함께 "2분 동안 사람들에게 보여 주고 싶은 것은 뭐예요?"라고 물어요 | 주제 |
| 주제와 관련된 것만 읽어요: 내 커밋, 공부 노트, GitHub 이슈와 PR, `claude-mem` | — |
| 찾은 것과 읽지 못한 것을 보여 줘요. "이 로컬 저장소를 기준으로 보면 될까요?"라고 묻고, 팀 로그도 제안해요 | 기준 저장소, 더 볼 자료, 그 밖에 알려 줄 내용 |
| 동기, 가져갈 한 줄, 슬라이드 수(약 6 ± 2) 중 아직 안 정한 것만 물어요 | 각 항목 |
| 이야기 구조(오프닝 → 도입 → 전개 → 전환 → 마무리, 또는 증상 → 증거 → 원인)와 오프닝 | 구조와 오프닝 |
| 제목 슬라이드(요점을 먼저)와 마지막 문장 | 두 문장 |
| 슬라이드마다 주장 한 문장과 `Show` 줄. `Show` 줄은 청중이 그 슬라이드에서 볼 한 가지예요 | 각 주장과 `Show` 줄 |
| 어떤 슬라이드에 어떤 실제 출력을 넣을지 정하고, 명령을 다시 실행해 `evidence/`에 저장해요 | 증거 목록 |
| 청중이 모를 수 있는 용어 | 용어와 화면에 보여 줄 정의 |
| "발표 스크립트를 먼저 만들까요?" | 예: 고쳐 쓸 스크립트 초안을 받아요. 아니요: 나중에 가벼운 노트를 받아요 |
| "이 내용으로 디자인을 정할까요?" | `design`으로 넘어가기 |

### design — 스타일 정하기

| 스킬이 하는 일과 묻는 말 | 내가 정할 것 |
|---|---|
| 저장한 DESIGN.md가 있으면 "이번에도 이 스타일로 갈까요?"라고 물어요 | 그대로 쓰기, 또는 새 스타일 고르기 |
| "원하는 디자인 레퍼런스가 있어요? (사이트 URL, 이미지, DESIGN.md)"와 "getdesign.md 레퍼런스 중에서 고를까요?" | 레퍼런스, getdesign.md 브랜드, 또는 둘 다 아님(그러면 `frontend-slides` 스타일이나 프리셋) |
| `previews/`에 미리보기 두세 개를 만들어요 | 미리보기 하나 |
| (직접 요청할 때만) 빠르게 참고할 디자인을 달라고 하거나 올라온 사례를 말하면 `cases/`의 발표 2~3개를 미리보기와 함께 보여 줘요 | 기준이 될 발표 하나, 필요하면 다른 발표의 도식 부품 |
| 강조색과 그 출처를 보여 줘요: "강조색은 `<color>`이고, `<from>`에서 가져왔어요. 이 색으로 갈까요, 다른 색을 고를까요?" `<from>`은 DESIGN.md 키 같은 출처예요 | 유지 또는 다른 색. 처음이면 다음 발표에도 쓸지까지 |
| "이 디자인으로 발표 자료를 만들까요?" | `build`로 넘어가기 |
| 한 번만 말하고 기다려요: "새 세션에서 '/jungle-deck 이어서'라고 입력하면 가볍게 이어져요. 여기서 계속하려면 '계속'이라고 해 주세요." | 새 세션 시작, 또는 "계속" |

### build — 첫 초안

| 스킬이 하는 일과 묻는 말 | 내가 정할 것 |
|---|---|
| 틀과 내 내용, 내 스타일로 `<slug>.html`을 쓰고, 이미지를 `<slug>.assets/`에 복사해요 | — |
| `Show` 줄이 순서, 분기, 경로, 배치, 수량을 말하면 그 슬라이드에 도식을 그려요. `Show` 줄이 말한 것만 그려요 | — |
| 내 스크립트(또는 가벼운 노트)를 발표자 노트에 넣어요 | — |
| `scripts/check_layout.py`를 한 번 실행해 넘침, 겹침, 12 px보다 작은 도식 글자를 찾아요(Chrome, Chromium, Edge가 없으면 건너뛰어요) | — |
| 로컬 서버를 켜고 `http://127.0.0.1:<port>/<slug>.html` 주소를 알려 줘요 | — |
| 브라우저에서 첫 초안을 보고 말해 달라고 해요 | 고칠 점, 또는 `revise`로 넘어가기 |

페이지 단축키: `→` 다음, `N` 노트, `E` 편집, `Ctrl+S` 저장, `?` 전체 단축키. 편집 중에 `Tab`을 누르면 고른 글의 크기 버튼(글자 크기, 상자 너비)이 열려요. 페이지가 요청하면 `R`로 새로고침해요.

### revise — 고치기 반복

| 스킬이 하는 일과 묻는 말 | 내가 정할 것 |
|---|---|
| — | 페이지에서 글, 크기, 노트를 고치고(`E`) 저장한 뒤(`Ctrl+S`) "저장했어, 봐줘"라고 말하기 |
| 저장 내용을 읽고 실수처럼 보이는 변경을 알려 줘요 | 유지 또는 되돌리기 |
| 내 글과 크기를 그대로 두고 레이아웃, 슬라이드 나누기, 증거를 손봐요 | 새 슬라이드의 주장(후보 중에서) |
| 내가 말한 대로 도식을 바꿔요. 편집 모드에서는 도식 안의 글자를 고칠 수 없어요 | 도식에서 바꿀 내용 |
| 페이지를 고쳐요. 페이지가 `R`을 누르라고 알려 줘요 | — |
| 끝났는지 묻지 않아요 | "발표 자료 게시"라고 말해 `publish`로 넘어가기 |

### publish — 커밋과 배포

| 스킬이 하는 일과 묻는 말 | 내가 정할 것 |
|---|---|
| `evidence/` 파일과 토큰처럼 보이는 문자열을 보여 줘요(저장 폴더가 git 저장소일 때) | 항목마다 가리기, 빼기, 유지 |
| "이 발표 페이지를 따로 배포할 생각이 있어요?" | 아니요(로컬 HTML에서 멈춰요), GitHub Pages, 또는 다른 호스트(경로를 알려 줘요) |
| Pages를 고르면 Pages 저장소 경로, 배포 폴더(`gh`로 못 읽을 때만), 페이지 URL을 물어요 | 각 항목 한 번씩. 다음 게시 때 다시 써요. 소스가 `gh-pages` 브랜치이면 로컬 HTML에서 멈춰요 |
| 페이지를 Pages 저장소에 복사하고, 인덱스에 카드가 있으면 카드 초안을 써요 | 카드 문구 |
| 저장소별 커밋할 파일, URL, 카드를 한 메시지로 보여 주고 "커밋하고 푸시할까요?"라고 물어요 | 커밋하고 푸시할지(질문 하나). 예라고 하면 다시 묻지 않고 커밋하고 푸시해요 |
| 라이브 페이지가 응답하고 내용이 일치할 때까지 기다려요 | — |
| 스타일을 DESIGN.md로 저장할지 묻거나, 내 파일과 달라진 점을 보여 줘요 | 새 파일, 교체, 아니요. 또는 적용할 변경 |
| 발표 자료가 끝났는지 물어요 | `phase: done` |

## 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| WSL에서 Windows 브라우저로 `http://127.0.0.1:<port>/...`가 안 열려요 | `.wslconfig`에 `localhostForwarding=false`가 있어요 | 그 줄을 지우고 `wsl --shutdown`을 실행하세요. 또는 스킬에게 말하고 서버 없이 작업하세요. 페이지를 파일로 열면 `Ctrl+S`가 내보내기가 되고, 스킬이 내보낸 파일을 합쳐요 |
| 페이지에 "서버가 꺼져 있어요"가 보여요 | revise 서버가 멈췄어요. 예를 들어 Claude Code 세션이 끝난 경우예요 | "서버 다시 켜줘"라고 말하세요. 주소가 같으면 `Ctrl+S`를 다시 누르세요. 주소가 바뀌면 저장하지 않은 편집은 이전 주소에 남아요. 실패한 저장은 다운로드 폴더에 있고, 스킬이 합쳐요 |
| 저장해도 스킬이 반응하지 않아요 | 이 세션에서 `Monitor` 도구를 쓸 수 없어요 | 저장할 때마다 "저장했어, 봐줘"라고 말하세요. 이것이 기본 흐름이에요 |
| 설정을 저장할 때마다 Claude Code가 권한을 물어요 ("... which is a sensitive file") | 2026-10-26 이전에 설치했다면 `jungle-deck.local.md`가 `~/.claude` 아래 스킬 폴더에 있어요. Claude Code는 그 위치를 고칠 때마다 물어요 | 스킬을 업데이트하세요(스킬 폴더에서 `git pull`). 파일이 `~/.config/jungle-deck/`로 옮겨져요. 그전까지는 매번 허용하세요. `claude --permission-mode bypassPermissions`를 쓰면 묻지 않지만, 다른 권한 확인도 모두 꺼져요 |
| "에이전트 수정과 겹쳐요" | 나와 스킬이 같은 슬라이드를 고쳤어요 | "겹친 거 합쳐줘"라고 말하세요. 내 글이 우선해요 |
| "저장이 안 됐어요 (HTTP `<n>`)" | HTTP 403이면 페이지를 서버 주소로 열지 않은 거예요 | 스킬이 알려 준 주소를 여세요. 실패한 저장은 다운로드 폴더로 내보냈으니 스킬에게 말하세요 |
| "저장 안 된 편집이 있어요 (`<ids>`) — 그 뒤에 파일이 바뀌었어요" | 브라우저에 저장하지 않은 편집이 남아 있는데, 그 뒤에 파일이 바뀌었어요 | "복원"을 누르세요 |
| "에이전트 수정 뒤 내 저장 문구가 바뀌었어요" | 스킬이 고치면서 내가 저장한 글이나 크기가 바뀌었어요 | "복원"을 눌러 내 저장으로 되돌리거나, "그대로 두기"를 눌러 스킬의 버전을 유지하세요. 그다음 스킬에게 어느 쪽인지 말하세요 |
| "글이 상자를 넘쳐요" | 글이 상자나 슬라이드에 맞지 않아요. 크기를 바꾼 뒤에 자주 생겨요. 편집 모드(`E`)에서는 그 상자가 표시돼요 | 스킬에게 레이아웃 조정을 부탁하세요. 스킬은 내 글과 크기를 그대로 두거나, 바꿀 내용을 제안해요 |
| "에이전트가 슬라이드를 지웠어요" | 내가 저장한 슬라이드가 파일에서 사라졌어요 | 스킬에게 일부러 지웠는지 물어보세요. 일부러 지운 게 아니면 스킬이 수정 전 상태로 되돌려요 |
| 도식 안의 글자를 고칠 수 없어요 | 편집 모드는 SVG 안의 글자를 바꾸지 못해요 | 스킬에게 바꿀 내용을 말하세요. 예: "이 경로만 강조해 줘" |
| 라이브 페이지 확인이 시간 초과돼요 | GitHub Pages가 아직 빌드 중이에요 | 나중에 다시 확인해 달라고 하세요. 다시 푸시하지 마세요 |
